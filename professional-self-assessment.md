# Professional Self-Assessment

Completing the Computer Science program and developing this ePortfolio has given me the opportunity to reflect on how my technical skills, professional goals, and understanding of computing have evolved. When I entered the program, my primary focus was learning how to build functional software and strengthen my programming foundation. Through coursework in software development, testing, algorithms, databases, graphics, and secure coding, I developed a broader perspective. I learned that effective computing solutions must not only function correctly, but also be maintainable, efficient, secure, documented, and aligned with organizational needs. My ePortfolio demonstrates this growth through three enhancements that address software engineering, algorithms and data structures, and database security.

My professional direction also became clearer during the program. I initially viewed my future primarily through software development and cybersecurity roles. As I learned more about secure design, access controls, risk analysis, and the consequences of weak technical controls, my interests expanded toward IT audit, cybersecurity, risk management, and governance, risk, and compliance roles. I became more interested in understanding not only how systems are built, but also how technical design decisions affect organizational risk, compliance, security, and decision-making. Coursework in secure coding and software quality assurance helped reinforce that security must be incorporated throughout the development lifecycle rather than added after a system is complete.

Collaboration and communication have been important parts of my development as a computer science professional. Although the primary artifacts in this portfolio were individually authored projects, I developed collaborative habits through peer feedback, requirements-based development, testing activities, technical documentation, and code review. The CS 499 code review required me to evaluate existing code, identify weaknesses, explain technical trade-offs, and communicate planned improvements to an audience of peers or managers. The written enhancement narratives and GitHub Pages portfolio further strengthened my ability to adapt technical information for different audiences. Developers may need implementation details, while managers, auditors, or stakeholders may need to understand the security, performance, usability, or organizational impact of a technical decision. Learning to communicate those differences clearly is one of the most valuable skills I developed throughout the program.

The software engineering and design artifact in this portfolio is my CS 330 OpenGL Castle Scene. The original application successfully rendered a three-dimensional scene using C++, OpenGL, GLFW, GLEW, and GLM, but its scene data and rendering logic relied heavily on hardcoded values. The enhancement transformed the SceneManager into a more data-driven and maintainable component by moving scene settings into JSON configuration, adding structured logging, validating external data, providing safe fallback behavior for missing textures, and replacing inline rendering logic with named helper functions. This work strengthened my understanding of modular design, configuration management, defensive programming, and low-level application behavior. It also showed me how improving reliability and maintainability can create value beyond simply adding new functionality.

My CS 320 Contact Service enhancement strengthened my understanding of algorithms, data structures, testing, and design trade-offs. The original project used a single HashMap, which supported efficient contact ID lookups but limited last-name searching. I improved the service by implementing a dual-index design with a HashMap for contact ID access and a TreeMap for ordered last-name indexing. This allowed the application to preserve efficient ID retrieval while supporting more efficient ordered and prefix-based searches. I also consolidated repetitive update methods, added a specific ContactNotFoundException, trimmed String input before validation, and expanded testing for edge cases. This enhancement reinforced that selecting a data structure is not only a coding choice; it is a design decision that affects performance, maintainability, consistency, and future scalability.

The CS 340 Grazioso Salvare Dashboard demonstrates my growth in database development, application security, and organizational risk awareness. The original dashboard connected a JupyterDash interface to a MongoDB database and displayed filtered animal shelter data, visualizations, and location information. However, it contained weaknesses that would create security and governance concerns in a professional environment, including plaintext credentials, limited query protection, unrestricted operations, and no explicit indexing strategy. I enhanced the project by moving credentials into environment-based configuration, implementing recursive NoSQL query sanitization with an allowlist of approved operators, applying role-based access control, and creating indexes for common rescue-filter queries. I also improved dashboard error handling, empty-data behavior, and map-column handling. These improvements helped me understand how database design connects directly to confidentiality, integrity, availability, auditability, and organizational decision-making.

Together, the three artifacts demonstrate the five Computer Science program outcomes. I addressed collaborative environments and organizational decision-making by designing a dashboard that supports information access while modeling least-privilege access through role-based controls. I strengthened oral, written, and visual communication through my narrated code review, enhancement narratives, documentation, and portfolio presentation. I demonstrated algorithmic thinking through the HashMap and TreeMap dual-index structure and the associated performance trade-offs. I applied well-founded and innovative techniques through JSON-driven configuration, structured logging, unit testing, database indexing, and secure configuration management. Most importantly, I developed a stronger security mindset by incorporating validation, exception handling, input sanitization, least-privilege access, secure credential management, and defensive design across the artifacts.

The artifacts in this ePortfolio work together as a unified demonstration of my growth. The CS 330 artifact shows how I improved a software system's maintainability and reliability. The CS 320 artifact demonstrates how I evaluated data structures and optimized a computing solution based on performance needs. The CS 340 artifact shows how I applied secure database practices and governance-oriented thinking to a user-facing application. Together, they represent my transition from focusing primarily on functional software development toward creating secure, efficient, maintainable, and auditable systems.

As I move forward, I plan to continue building technical knowledge in cybersecurity, cloud security, IT audit, risk management, and GRC. My study of emerging areas such as artificial intelligence governance and Zero-Trust security has reinforced the importance of combining technical expertise with responsible oversight. This ePortfolio provides evidence of my ability to analyze systems, identify weaknesses, justify improvements, communicate technical decisions, and design computing solutions with security and organizational value in mind.
